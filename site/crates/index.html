Eight crates, each honest about itself

None of the eight manifests carries a description field, so the descriptions below come from each crate's own README. Several of those READMEs open with a Status section, which makes them the best maturity signal in the repository.

0.1.0 in every manifest MIT OR Apache-2.0 edition 2021

Composition root

CrateOwnsDeclared status
doob The primary library and command-line application. Combines the domain ports from doob-core, a selected storage adapter, HANDOFF YAML sync, GitHub issue sync, rendering, and command dispatch. Library plus binary. Active SurrealDB-backed CLI, todo and note commands, kanban, search, stats, handoff sync, GitHub sync, archive.
Partial SQLite covers todo, note, handoff status, and handoff session persistence, but several CLI paths are incompatible.
Experimental the Beads adapter is a library API with no CLI command, and schema is a partial manifest.

Domain and storage

CrateOwnsDeclared status
doob-core Backend-independent models, repository ports, context helpers, query validation, record-id helpers, exit-code classification, and the shell status cache. No workspace dependencies. Active
doob-surrealdb The default persistence adapter. Embeds SurrealDB 2 with the SurrealKV engine and implements the todo, note, HANDOFF item, and archive repository ports. Active
Test coverage the crate has no direct unit or integration test files of its own; its behaviour is exercised by the doob integration suite.
doob-sqlite An optional SQLite adapter using rusqlite with a bundled library, storing structured collections as JSON text. Opts out of doob-core's default features. Partial and experimental Todo, note, handoff item, session log, session state, and checkpoint operations are implemented. Archive persistence, raw query execution, and the raw HANDOFF sync operations are not.

The SQLite crate's README contains the most important sentence in the repository for anyone about to use it: create_todos interprets tuple fields as (content, uuid, …) while the command layer and the SurrealDB adapter pass (uuid, content, …). Until that is reconciled, the README's guidance is that the SQLite-backed doob todo add path should be considered unsafe for real data. Direct library callers should follow the adapter's current order.

Sync

CrateOwnsDeclared status
doob-sync The provider-neutral domain for pushing todos to external issue trackers: serializable sync types, capability-oriented provider traits, and SyncService. No workspace dependencies. Domain the types and the Beads integration are implemented and unit-tested.
Not wired the provider framework is not connected to any doob CLI command, and there are no active GitHub, Linear, Jira, or bidirectional providers in this workspace.
doob-beads A synchronous adapter from doob-sync to the external Beads bd command-line tool. Depends on doob-sync only. Not active in the CLI the main crate re-exports the adapter, but no current command constructs a SyncService with it.
doob-gh GitHub issue sync by invoking the authenticated gh CLI. Owns project-to-repository mapping, local sync state, issue body construction, and the create, close, and comment actions. Active 111 issues across real repositories on the last dry run.
Separate does not implement the doob-sync provider traits; it has zero references to that crate.

Two sets of Beads tests are gated behind feature names — bd and integration-tests — that are not declared in the doob crate's manifest. Four test functions are therefore permanently inert in normal workspace builds.

Dashboard

CrateOwnsDeclared status
doobdash A standalone Ratatui terminal dashboard for browsing and updating a HANDOFF YAML file. Binary only, no library target, and no dependency on any doob crate. Active item, log, statistics, help, search, detail, and navigation views.
Partial status and note actions shell out to doob, and failures are currently discarded by the event handlers rather than shown in the TUI.
Experimental the DB tab is implemented but its namespace and field mapping do not match the primary adapter, so it may show no rows or skip valid todos.

Five tabs: Items (a three-column Active, Waiting, Done kanban), Log, Stats, Help, and DB. Path discovery walks up from the working directory for a HANDOFF.*.yaml, excluding HANDOFF.state.yaml.
