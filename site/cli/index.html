Command line

Eleven commands, and a global --json

The self-description is Modern todo management for coding agents. Output blocks below are captured from the installed binary against a live database unless the caption says otherwise.

cargo install --path crates/doob exit 0–6

Surface

doob --help
Modern todo management for coding agents

Usage: doob [OPTIONS] <COMMAND>

Commands:
  todo     Manage todos
  note     Manage notes
  kan      Visual kanban board of todos
  search   Full-text search across todos and notes
  stats    Analytics and statistics
  archive  Archive completed/cancelled todos
  handoff  Manage handoff items (bidirectional sync
           with HANDOFF.yaml)
  tui      Launch the doobdash TUI dashboard
  watch    Live-updating kanban board
  schema   Print machine-readable JSON manifest
  help     Print this message

Options:
      --json     Output in JSON format
      --db <DB>  Database path
  -h, --help     Print help

There is no --version. Running it returns error: unexpected argument '--version' found — the Cli struct has no version attribute. The version is discoverable through doob schema instead, where it reads 0.1.0.

Read paths take JSON

--json is a global flag, so it goes before the subcommand. The agent guide calls the JSON shape a compatibility surface — treat a change to it as a breaking change.

The id field is a nested SurrealDB Thing — id.tb and id.id.String — not the flat "todo:abc123" the root README shows. The manifest is the real shape.

doob handoff sync rewrites the YAML file. The summary it prints reports what was created, updated, and pulled.

Call doob handoff update-status <id> <status> before editing status by hand. On a conflict the database wins and is written back into the file, so a manual status edit that skips this step is reverted on the next sync.

There is no undo for a remove, which is why a backup hook runs before it in this workspace's agent configuration.

Commands that do not exist

The root README and docs/sync/ document a provider sync framework as if it were reachable from the CLI. It is not. There is no sync subcommand at all.

DocumentedReality
doob sync config beads --enableno such subcommand
doob sync to --provider beadsno such subcommand
doob sync status, doob sync providersno such subcommand
doob todo add --duenot implemented a plan and a design exist in docs/
bd list, bd closea third-party CLI the Beads tool, not a doob command

The per-crate READMEs are the reliable source. The root README.md has drifted on the install command, the database path, and the JSON id shape as well.
